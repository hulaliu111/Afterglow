# Afterglow 产品自动演示功能开发提示词

## 角色与任务

你是 Product Showreel Director、Motion Designer 和前端动画工程师。
请为现有 Afterglow 网站增加一个可播放的约 30 秒产品演示功能，让第一次访问的人看懂：如何从“不知道看什么”，找到一部想看的电影或剧集，并留下推荐。

交付的是网站内可播放、可暂停、可重播的产品演示。它使用真实界面与真实数据，不能只交付分镜说明，也不能用几张网页截图轮播代替实现。

先阅读项目，再编排镜头，最后实现和验证。不要重做整个网站。

## 先理解现有产品

项目是纯 HTML / CSS / JavaScript 静态网站，兼容 GitHub Pages。
核心文件：README.md、index.html、style.css、app.js、data.js、series.js、data/series_catalog.json，以及本地 posters/。

品牌：Afterglow。
品牌文案：好故事，自有余韵。
视觉：暖黑、琥珀色、克制的衬线字体和留白。
用户：想找到值得看的电影或剧集，又不想花太多时间挑选的人。
核心价值：用少量操作，找到一个愿意开始看的好故事。

现有功能包括：
- 今日一幕：电影 / 剧集切换和按日期推荐。
- 探索片库：片名搜索、地区 / 题材 / 年代筛选、排序和结果数量。
- 精选剧集：美剧、英剧、韩剧入口；具体季、集数和约单集时长。
- 为我选一部：按当前作品类别、题材或年代随机推荐。
- 封面弹窗：用户认可的第一版整张海报 3D 倾斜、随鼠标变化的光泽、后景阴影和虚化背景。
- 查看站内推荐、复制推荐、保存分享图片。

以上以实际代码为准。展示数量和评分从数据生成，不把当前 250 部电影、60 部剧集写死在演示文案中。
没有的功能不要编造，例如 AI 推荐、账户、收藏夹、播放影片或在线观看。

## 产品故事与镜头主次

主故事：
进入今日推荐 → 想找一部英剧 → 打开片库 → 选择英剧和悬疑题材 → 看见匹配结果 → 选择作品封面 → 查看原有 3D 封面 → 进入作品介绍 → 保存分享卡 → 留下一个想看的好故事。

先验证目录中有适合这条路径的作品，再确定演示样本。例如可优先检查《神探夏洛克》第 1 季。若实际分类不匹配，调整演示筛选，不伪造筛选结果。

三个主要结果必须被看懂：
1. 有偏好时，能快速缩小选择范围。
2. 选中作品后，能看到推荐理由和观看所需时间。
3. 一部想看的作品，可以通过分享卡留下来。

日期翻页、日间主题、口碑榜和人物合集是辅助功能，不需要全部塞进 30 秒。
封面 3D 是短暂的观感展示，不应盖过选片的过程。保留第一版整张原海报的效果，不重新做人像抠图、人物背景分层或自动漂浮。

## 播放功能

- 给网站增加低调的“看看 Afterglow 如何选片”入口，用户点击后才播放。
- 用独立演示容器隔离演示状态，不改变用户当前的作品、日期、筛选条件或 URL，也不覆盖原站的分享逻辑。
- 提供播放 / 暂停、重播、进度和关闭；关闭后回到原界面并恢复键盘焦点。
- 演示时间以一个明确的时间轴为准。暂停时所有产品动画和镜头同时停止；重播必须从相同起点开始。
- 演示数据固定选取当前目录里的真实作品，避免随机推荐让每次播放的分镜不同。
- 预加载本地海报，资源失败时提供合理降级。
- 演示中的“保存分享卡”展示真实生成的卡片预览，不触发自动下载，也不改写系统剪贴板。下载或复制由用户在真实产品中主动执行。
- 演示结束后提供“开始选片”，回到真实产品。
- 兼顾桌面和手机；尊重 prefers-reduced-motion。减少动态模式下使用静态步骤或简单切换，仍然能理解完整过程。

## 建议 30 秒分镜

按 30fps 编排，F000–F899 为全片。以下是导演起稿，可以依据真实界面调整，保持总时长约 25–35 秒。

F000–F090｜今日一幕，直接进入产品
从真实推荐卡开始，海报、片名与一句推荐理由建立产品。品牌保持在界面中，不安排长 Logo 开场。下一操作在镜头末尾提前出现。

F082–F225｜带着偏好进入片库
用户打开“探索片库”，选择“剧集”，再选择“英剧”。依次呈现选中标签、匹配列表和真实结果数量。镜头靠近正在操作的筛选区域。

F216–F375｜从许多选择变成一个想看的故事
选择“悬疑”，结果卡片根据真实筛选变化。让目标作品进入视觉中心，片名和评分来源可读。用这张封面作为下一镜头的交接对象。

F366–F510｜由封面进入作品
目标封面从片库位置连续放大进入封面弹窗，保留相同图像与轮廓。短暂演示第一版轻微 3D 倾斜和光泽，然后点击“查看作品介绍”。不拆分人物，不让整个 UI 旋转。

F501–F660｜找到值得开始看的理由
同一作品的封面和标题交接到真实推荐卡。让推荐理由、所选季、集数、约单集时长成为主焦点。至少留出一段能读懂结果的时间，再引入保存操作。

F651–F825｜把这部作品留下来
点击“保存分享卡”，同一海报与作品标题进入真实分享卡样式，完成内容排版和卡片预览。重点是作品信息被完整保留，不使用与功能无关的成功图标或假下载提示。

F816–F899｜价值收束
分享卡作为主对象，带出 Afterglow 与“好故事，自有余韵。”，随后出现“开始选片”。保持克制，不在最后堆叠多个功能。

相邻镜头约 4–12 帧重叠。重叠用于封面、标题、标签等对象交接，不用于强迫所有元素一直运动。

## 视觉与运动标准

参考高质量 Apple / Linear / Arc 产品演示的清晰、连贯与克制，并保持 Afterglow 自己的暖黑与琥珀色。

- 使用真实 UI 和真实作品，不贴一张完整网页截图做全局缩放。
- 每个主要镜头都要有：用户动作 → 系统响应 → 可读结果 → 下一交接对象。
- 一个时刻只有一个主要焦点。稳定结果回到画面中央，重要操作区域可占画面 45%–70%。
- 安排 2–3 次有意义的较大镜头运动，例如筛选区到结果卡、封面到弹窗、推荐卡到分享卡。
- 产品对象交接至少保持内容、形状、位置、尺度或运动方向中的两个连续属性。
- 筛选反馈按“标签选中 → 列表重排 → 数量更新”错峰表现，但所有结果必须对应同一份真实筛选数据。
- 镜头、容器、卡片使用不同缓动和节奏，避免一起开始、一起停止。
- 重要片名和操作文字在 1280×720 输出中应清晰可读，建议约 20px 或更大。
- 推荐结果、季信息和分享结果可停留约 1–2 秒。阅读时间优先，不为了“连续 9 帧不能静止”添加装饰运动。
- 不强求 60–90 个变化。只保留帮助理解产品的动作，宁可少而清楚。
- 不使用粒子、无意义数字滚动、整页呼吸、抖动、密集闪光、大段字幕或大量模糊转场。
- 除展示已有封面 3D 功能外，UI 保持横平竖直。
- 背景只辅助空间感，关闭背景动画后，产品故事仍然成立。

## 实现约束

优先复用现有样式、作品数据和纯函数；需要时抽取小范围可复用逻辑，避免复制两套不一致的筛选算法。

优先用现有 HTML / CSS / JavaScript 与浏览器动画能力完成。不要为了 30 秒演示迁移整个项目、引入大型框架或增加后端服务。

将分镜、时间段、交接对象和演示数据组织成清晰的结构。动画由统一时间轴驱动，布局计算与播放逻辑分开。

保留原网站的日推、片库、封面弹窗、分享、移动布局和 GitHub Pages 兼容性。完成本地可运行预览，不自动发布。

## 交付与验收

先输出简短的产品理解、最终内容链、帧级导演方案和转场对象表，然后实现。

最终交付：
1. 网站内可实际播放的演示入口、播放器和完整演示。
2. 时间轴与分镜说明，注明每场的用户动作、系统响应、结果和交接对象。
3. 六张关键画面：推荐建立、筛选操作、目标作品出现、封面展示、推荐结果、分享卡与品牌。
4. 一次 Motion Audit：关闭纯背景动画，检查产品行为是否仍能完整讲故事。
5. 桌面与窄屏验证；播放、暂停、重播、关闭、焦点恢复和减少动态模式验证。

验收问题：第一次看的人能否说清“这是一个电影和剧集推荐网站，我能按偏好找到作品、查看推荐、保存分享卡”？

不要只说明可以怎么做。完成可运行的本地功能，并给出预览结果及实际验证结论。
